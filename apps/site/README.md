# EchoScript public site

The separate Symfony 7.4 LTS / PHP 8.4 site serves product information and the currently verified Android download. Twig renders accessible HTML; AssetMapper serves local fingerprinted assets and an importmap-managed Stimulus appearance control. It accepts no audio or evidence uploads. The Vue workbench, Node provider service and Fumadocs documentation retain separate applications and deployments.

From the repository root:

```sh
npm ci --ignore-scripts
npm run build:site-css
composer install --working-dir=apps/site --no-scripts
php apps/site/bin/console importmap:install
APP_ENV=prod APP_DEBUG=0 php apps/site/bin/console asset-map:compile
php apps/site/tests/smoke.php
php -S 127.0.0.1:8080 -t apps/site/public
```

For a local development server, use the PHP built-in server only on loopback. Deploy with a supported PHP 8.4 runtime and document root `apps/site/public`; publish only that public directory while retaining the application and `downloads/current.json` on the host. Generate a deployment-specific `APP_SECRET` if introducing secret-dependent framework features. The current portal has no session or authentication flow.

The source stylesheet in `styles/app.css` is compiled with Tailwind; `assets/styles/app.css` is build output and must be rebuilt before AssetMapper compilation. Palette values come from `packages/ui/theme.css`. `downloads/current.json` is the release-link/checksum source for this portal; advance it only after verifying the exact replacement APK and release assets. The available APK and in-progress source update are labeled separately.

`.github/workflows/site.yml` validates PHP/container/Twig, compiled assets, real kernel responses, methods, links and dependency advisories. `.github/workflows/importmap-updates.yml` runs on Mondays at 06:17 UTC and supports a manual dry run. It targets `apps/site`, pins reviewed actions and installs Composer dependencies without application scripts. The original recipe's unavailable Composer action tag was replaced with the equivalent direct Composer command.

For scheduled PR creation, repository Actions settings must permit `GITHUB_TOKEN` to create pull requests. PRs generated with that token do not automatically trigger other workflows; run the validation workflow manually on an update branch and review it before merging. No PAT, broader GitHub App grant or automatic merge is configured. The updater maintains only its own branches/PRs. Local importmap entries are left alone; the pinned Stimulus dependency is checked for updates and advisories.

The public portal can also be generated by the real Symfony kernel for static hosting: run `php apps/site/tools/export-static.php qa-output/site-static`, then `node tools/package-hosted.mjs qa-output/site-static` from the repository root after building the web app and compiling site assets. `npm run build:hosted` performs this sequence when PHP and Composer dependencies are available. The output has the Twig-rendered portal at `/` and the Vue app at `/workbench/`, keeping the app worker's scope separate. This is static publication of Symfony output, not PHP execution on Sites. Vercel retains the separate Next.js docs app. Deployment success is recorded only after the hosting service confirms it.
