---
title: "Architecture and boundaries"
description: "EchoScript reference: Architecture and boundaries."
---

EchoScript is designed to support defensible forensic-audio analysis, transcription, evidence preservation, and chain-of-custody workflows. Technical consistency does not establish legal admissibility or certify an organization/deployment.

- `apps/android`: Kotlin/Compose client. Persistent source evidence uses Tink Streaming AEAD AES256_GCM_HKDF_1MB. Its keyset uses explicit Tink authenticated encrypted serialization with an Android Keystore master key; reads reject plaintext compatibility fallback, and authenticated legacy keysets migrate without changing data keys. Source import hashes original bytes before any decode, uses bounded 64 KiB buffers, commits with an atomic rename, and writes immutable encrypted manifest snapshots. Android backup/device transfer are excluded. Reset/key loss is unrecoverable without a separately exported package. The native workbench adds bounded PCM decoding and DSP, spectral analysis, offline Vosk and optional ClearVoice, examiner revisions, microphone intake and explicit verified package transfer. Local render/Vosk requests use encrypted persistent job records, generic foreground progress and verified completed-pass reuse; remote approval and credentials are never queued. The APK includes pinned Vosk and ClearVoice model assets; optional companion processing requires explicit payload approval. See [Android boundaries and usage](/docs/android/offline).
- `apps/web/src`: worker-based browser workbench. Original bytes are copied into an in-memory immutable artifact store, with a 16 MiB source / 64 MiB workspace policy. It is not equivalent to the Android vault. Web exports require explicit download and secure destination handling. Package encryption uses Web Crypto AES-256-GCM with PBKDF2-HMAC-SHA256 (600,000 iterations, random salt/IV); it does not claim resistance to weak passphrases or replace device key custody.
- `packages/evidence`: canonical JSON, SHA-256, audit linkage, immutable artifact/provenance graph, revision pointers, case packages, transcript normalization/review. `specs/json-schema/case.schema.json` is authoritative. The build generates a standalone validator so browser CSP does not need `unsafe-eval`.
- `packages/audio`: deterministic classical JavaScript DSP, PCM WAV handling, FFT/Hann spectrogram analysis and conservative multi-feature speech-event candidates. Offline renders create separately hashed PCM16 WAV derivatives. Scores/candidates do not establish that speech is present.
- `crates/audio-core`: bounded streaming Rust PCM16 desktop utility (64 KiB processing buffer), gain and high-/low-pass/notch filters. It is not yet the Android DSP implementation. No custom cryptographic primitives are implemented here.
- `services/api`: strict TypeScript/Fastify loopback service. Local bearer authentication, exact-origin CORS, one-use hash/duration-bound consent, bounded input/output, one concurrent decoder, finite timeouts and disposable subprocesses. The worker uses pinned Vosk weights, validates their file hashes, and writes no evidence files. No transcript/audio/token logging. This is not yet the planned OIDC/team gateway.
- `packages/exports`: valid TXT/JSON/HTML/CSV/SRT/WebVTT/CTM/DOCX/XLSX/PDF, with independently hashed outputs. Human edits invalidate old word alignment; CTM then fails rather than inventing timing.
- `tools/case-verify`: Android-independent Node CLI. ZIP verification streams with a 16 GiB desktop policy and checks schemas, bytes/hashes, CRC, provenance, audit linkage, inventory and sidecars. Encrypted browser packages remain bounded to 64 MiB.
- `packages/case-security` and `tools/case-protect`: shared Java integration of platform PBKDF2/ECDSA and maintained Tink. Native `ECHOCS01` containers stream encrypted case ZIPs; the independent JVM serves authenticated byte ranges to the Node ZIP verifier without plaintext staging. `checkpoint.schema.json` defines canonical P-256 historical snapshots stored as ordinary REPORT artifacts. See [the exact protocol, trust and recovery boundaries](/docs/evidence/protected-transfer).

Unsigned chains/checksums can be rewritten together by an attacker with full package access. Preserve package SHA-256 and signer fingerprints independently. Device checkpoints authenticate only their exact historical prefix; embedded keys and actor labels do not establish trusted identity. Enrollment, revocation, trusted timestamps, complete recovery and organizational custody procedures remain release work. Protected export recovery covers the exported snapshot, not later local changes or raw Keystore-key recovery.

No evidence is synchronized to Supabase by this implementation. The prior non-sensitive reference catalog remains separate. Multi-user identity, permitted-field preference sync and assignment portability are outstanding. Optional Whisper mediation is available only through the configured companion and exact-payload approval. Broader enterprise/cloud adapters, deployed identity, retention agreements and policy qualification remain outstanding.
