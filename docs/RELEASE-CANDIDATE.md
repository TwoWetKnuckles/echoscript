## Evidence controls and remaining acceptance

Preview 0.5.1 adds opt-in native streaming protected transfers, Keystore P-256 historical checkpoints and an independent JVM/Node verification path. See [the exact format, trust and recovery boundaries](evidence/PROTECTED-TRANSFER.md). These controls are not an authenticated examiner identity, revocation/attestation infrastructure, a trusted timestamp service or an approved recovery policy.

Desktop validation includes 30 Node tests, 9 JVM tests with the cross-runtime fixture enabled, and a real Tink-encrypted JVM-to-Node interoperability run, including wrong-passphrase, tag-tamper and no-clobber failures. Android compilation/emulator validation for these additions must be recorded against the resulting commit before claiming native success. CI now requires independent verification of seven native protected exports in addition to the existing core and interface subsets.

The first evidence-control commit `5199617a10a93f52a86de70a85e2359b322a908c` passed all seven quality jobs in [run 42402920191](https://github.com/TwoWetKnuckles/echoscript/actions/runs/42402920191), including API 29/36, the seven protected core exports per emulator and independent JVM/Node verification. Further source changes require their own checks; this does not pass the physical-device or complete application gate.

[Acceptance execution instructions](qa/RC-ACCEPTANCE.md) and the all-unpassed template record define the remaining evidence. `tools/release-gates.mjs` fails closed for missing gates, mismatched source/APK, changed referenced files, incomplete/subset workflows, runs before prerequisite approval, or fewer than seven consecutive complete results. It checks declared records and file consistency, not the truth or legal sufficiency of reviewer declarations. [Owner signing setup](android/OWNER-SIGNING.md) prepares a non-debug evaluation artifact only; owner key provision and upgrade/MDM acceptance remain outstanding.

The remaining acceptance column above continues to apply. No row becomes passed simply because a control or test harness exists. Physical-device measurements, complete native feature parity, team authorization/sync, owner production signing and deployment-specific governance remain mandatory.
