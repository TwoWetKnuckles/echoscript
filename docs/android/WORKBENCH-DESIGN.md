# Workbench design direction

The owner selected [Audio Editor: Recording Studio on the App Store](https://apps.apple.com/us/app/audio-editor-recording-studio/id1475947965) as an inspiration for the editing workflow. Its public screenshots show a prominent waveform timeline, highlighted time selections, nearby playback controls and compact effect tabs with sliders. EchoScript takes those general interaction ideas as a reference; its interface, branding and code remain its own.

The Android draft uses dark Material surfaces, a full-duration waveform with a separately identified spectral overview, draggable selection edges, direct playback and clipping controls, and grouped effect panels beneath the inspection tools. Exact time fields remain available for precision and accessibility. A short-range, configurable spectral view supports time/frequency inspection. An optional scan reads consecutive overlapping windows across the whole recording and reduces them to a coarse 128-column, 32-band view; the default quick overview still samples brief windows. Continuous high-resolution inspection across an entire long recording remains an open requirement. The full scan can be lengthy. Synthetic signal tests and Android 10/16 emulator workflows passed on `a59d28ef`; physical-device performance and acceptance remain open.

Presets and effect changes remain drafts until a render. The interface identifies enabled effects, retains signed numerical entry and records the actual processing recipe and input/output provenance. The latest test build groups presets and effect categories in compact horizontal strips, resets the individual-effect strip when changing groups, and places measurement tools after the main adjustments. Its interface checks passed on Android 10/16 emulators on `cc19e7a3`; physical review remains open. Region passes, restoration, limitations and validation status are described in [the workbench guide](ENHANCEMENT-WORKBENCH.md). A debug-only [free and premium plan preview](../PLANS.md) compares proposed access without accepting payments or changing existing evidence access. This design note does not imply that the draft is a released or physically validated build.
