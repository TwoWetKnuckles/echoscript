# Release acceptance execution record

The mandatory gates in [RELEASE-CANDIDATE.md](../RELEASE-CANDIDATE.md) remain in force. `specs/release-gates.json` enumerates them and the full workflow stages. There are no optional/waived states. This process records the exact configured build and deployment; it does not issue a compliance certificate or an admissibility opinion.

Copy `RC-ACCEPTANCE.template.json` into a protected validation directory outside the public repository. Populate the exact source commit and final APK SHA-256. Keep fixture provenance, sanitized measurements and independently reviewed policy records there. Never put real evidence, private case information, signing keys, credentials or confidential agreements in public CI/issues. Each evidence reference is a relative file path with its own SHA-256. The checker rejects missing/changed files, paths escaping the directory, absent/duplicate gates, unsupported results, partial runs and different build identities.

```sh
node tools/release-gates.mjs /protected/validation/record.json EXACT_SOURCE_COMMIT /protected/build/EchoScript.apk
```

Exit zero means the **declared record** has every gate marked PASS, its referenced files match, and seven consecutive full-workflow records cover the exact source/APK. It cannot establish that a declaration, screenshot, policy or device measurement is truthful, independently approved or legally sufficient. Qualified reviewers must inspect and approve the actual evidence. A failed or unavailable mandatory gate produces nonzero and `betaGate: NOT PASSED`. Do not edit a failure into a pass or omit the failed attempt. A code/APK change requires a new acceptance sequence.

Gate PASS requires a reviewer, acceptance UTC timestamp, concrete observation and at least one evidence file. Other results are `FAIL` or `NOT EXECUTABLE`, with a reason and null acceptance time. Full-run completion times must increase and occur after the other mandatory gates have been accepted. The seven-run gate is accepted only after the final complete run. Subset/other-build passes cannot be labeled full-run PASS. Failures reset the consecutive count. Every full workflow stage needs a PASS and a file reference; unsupported confidence/alternatives are tested for correct absence/disclosure, never fabricated.

A developer workstation/emulator is not a physical device report. A signed evaluation APK is not automatically a release candidate.
