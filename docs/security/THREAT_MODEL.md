# Security and evidence trust model

This is the current development implementation's model, not a claim that every risk is mitigated. Read [architecture](../architecture.md), [executed QA](../qa/STATUS.md), [SECURITY.md](../../SECURITY.md) and the [responsibility notice](../../DISCLAIMER.md).

Protect original acquired bytes, keys, case metadata, audit/provenance, derived audio, provider artifacts, transcripts and exports. Confidentiality and traceability are distinct from the truth of a recording, reliable identity attribution or legal authority to acquire/use it.

## Boundaries and residual risks

| Boundary / threat                                       | Current control                                                                                                                       | Residual limit / operator duty                                                                                                                                  |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Import → source store; alteration before/after decode   | Hash original bytes before decode; immutable artifacts and separately hashed derivatives                                              | Does not authenticate pre-acquisition events; preserve acquisition context and independent original copies                                                      |
| Android storage → device/backup reader                  | App-private persistent Tink streaming encryption; Keystore-wrapped keyset; backup/transfer exclusion; authenticated-read/tamper tests | Unlocked/rooted/compromised OS or privileged malware can exceed this boundary; reset/key loss may be permanent                                                  |
| Browser/session → closure, extension or injected script | Local bundled processing, worker separation, bounded memory and restricted hosting/CSP                                                | Memory is not durable storage; browser/extension/host compromise is outside this protection; export securely before closure                                     |
| Package → verifier; hostile archive/media               | Bounded parsing, path/inventory/schema/hash/CRC/provenance/audit checks; independent CLI                                              | Unknown decoder/parser defects and resource attacks remain possible; use isolated evaluation environments and retain failures                                   |
| Audit/checksums → full-package rewrite                  | Canonical hash linkage, external hashes and source 0.5 device-key P-256 historical checkpoints                                        | Embedded keys are not trusted identity; enroll/revoke fingerprints independently and review unsigned tails. Trusted timestamps remain unfinished.               |
| Client → local decoder                                  | Loopback binding, exact origin, random token, one-use hash/duration consent, bounded subprocess/timeouts                              | Not a multi-user authorization service; machine compromise or exposed token remains a risk; do not publish this API                                             |
| Device → external service                               | No cloud speech adapter/evidence synchronization implemented; explicit approval required for the configured local request             | Consent UI does not authorize a future remote service; provider contracts, retention and exact deployment must be qualified first                               |
| Automated transcript/restoration → examiner/report      | Provenance, uncertainty flags, actual provider score semantics, explicit human review revisions                                       | Incorrect/unsupported words, estimates and speaker mistakes need independent examination; a verification label is not legal authentication                      |
| Export → recipient/storage                              | Separate hashes; encrypted browser cases; source 0.5 Tink protected native transfer and independent JVM/Node verification             | Published 0.4 native cases, legacy ZIPs and individual exports remain plaintext. Password/recipient/destination, retention and recovery need approved controls. |
| Dependencies/build → distributed app                    | Lockfiles, pinned CI actions, model inventories, advisory/CodeQL checks and builds                                                    | Scans do not cover every vulnerability; signing/release custody, full supply-chain assessment and maintenance are deployer duties                               |

## Assumptions and exclusions

The trusted computing base includes the OS, platform key store, cryptographic libraries, build tools and software actually executed. The examiner supplies lawful authority, independent source custody, a trustworthy external checkpoint and an accurate acquisition narrative. Neither a device clock nor a manually supplied actor/speaker label is a trusted identity or timestamp service.

This build does not provide remote attestation, qualified electronic signatures, guaranteed key recovery, secure deletion from all copies, organizational identity/role enforcement or protection against a fully compromised endpoint. Source immutability inside a workflow does not physically prevent an administrator from replacing/deleting application files. Legal holds and disposal require organizational procedure.

Development release blockers include physical-device validation, advanced processing and diarization validation, resumable job recovery, qualified providers, team authorization/sync, independently approved signer enrollment/revocation and recovery, complete device/resource/security testing and seven consecutive complete application runs. Local subset passes remain labeled as subsets. A disclaimer is never mitigation for a correctable integrity/security defect. See [the exact checkpoint/container limitations](../evidence/PROTECTED-TRANSFER.md) and [acceptance execution record](../qa/RC-ACCEPTANCE.md).

Native review form text stays in ViewModel memory during navigation and configuration changes. Explicit saves create encrypted immutable transcript artifacts. Activity saved-instance state and preferences exclude transcript draft text. Process death can discard unsaved form edits, so save a revision before relying on it.

Acquisition titles and case search terms also remain in ViewModel memory rather than saved-instance bundles. These inputs survive configuration changes while the app process remains alive; process termination clears them.
